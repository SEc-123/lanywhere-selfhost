# Approved UDP extension wire contract — 2026-11-07

All integers little-endian. IPv4 addresses retain the existing protocol's numeric representation. TCP frame remains u16 length (type+body), u8 type, body.

- TCP CAPS request type 0x0b, empty body; CAPABILITIES response 0x89, u32 bits. Bits: 1 reservations, 2 lobby pages, 4 UDP fragmentation v1, 8 UDP nonce heartbeat, 16 full ScanFilter discovery, 32 provider selection, and 64 game metadata. The 0.4.2 self-host server advertised 31; the 0.4.5 self-host server advertises 127. Effective capabilities depend on the selected provider: the old public LANywhere adapter exposes 64, and LAN Play realms expose 78. These are adapter capabilities, not a claim that old upstream servers implement the extensions. Older servers may return 3 or unsupported error; clients fall back to legacy registration for small packets.
- UDP base: u32 magic 0x594e414c, u8 type, u32 member token (9 bytes). Downlink omits token.
- REGISTER_V2 type 0x04: base + u32 requestedFeatures (bits 4 and/or 8 only, nonzero). REGISTERED_V2 type 0x84: magic,u8 type,u32 acceptedFeatures (9 bytes). Server stores accepted bits per member. Request/ack have no extra bytes. Client should request available UDP bits from CAPS (12 on new server); match the expected type/feature reply.
- Legacy REGISTER 0x01 and REGISTERED 0x81 unchanged. Legacy registration sets member UDP features=0.
- DATA_FRAGMENT type 0x05: base9 + u32 destinationIP + u16 sourcePort + u16 destinationPort + u32 messageId + u16 totalPayloadLength + u16 offset + chunk. Header25, nonempty chunk<=1100. Total1..65507; offset+chunkLength<=total. Whole logical message is exactly the original UDP payload; ports/IP repeated and must match across fragments. Each sending session increments a u32 messageId; do not reuse within the 2-second assembly/replay window.
- DATA_FRAGMENT_IN type 0x85: magic4,type1 + u32 sourceIP + u16 sourcePort + u16 destinationPort + u32 messageId + u16 totalPayloadLength + u16 offset + chunk. Header21. Server chooses an outbound u32 ID for each forwarded logical datagram; each receiver reassembles by sender virtualIP+messageId within its current room/session. The destination is the receiving console, or broadcast already resolved by server. Chunk<=1100.
- HEARTBEAT type0x06: base9+u32 nonce (13 bytes). HEARTBEAT_ACK type0x86: magic4,type1,u32 nonce (9 bytes). Both exact lengths. Server accepts only when heartbeat was negotiated and UDP was registered; replies to observed source endpoint. Client checks server endpoint, type, exact size and outstanding nonce. Three consecutive unanswered heartbeat probes trigger V2 re-registration on the existing TCP/room; if registration still fails, surface UDP offline/reconnecting and do not keep a healthy InRoom status. TCP disconnect/reconnect uses existing RESUME and new UDP negotiation.

## Mixed clients

- Normal U_DATA 0x02 and DATA_IN0x82 formats remain unchanged. With negotiated bit4, new clients use old DATA for payload<=1100 and fragments above1100. Without bit4, they use legacy DATA through1455 bytes and explicitly reject larger sends with an upgrade diagnostic. Tests cover1101/1200/1400/1455 acceptance and1456 refusal.
- Server chooses format per receiver. Negotiated bit4 receivers get fragments for payload>1100; smaller payload gets legacy DATA_IN. Receiver without bit4 receives old DATA_IN only up to1459 payload (IPv4 MTU1500 after13 relay+28 IP/UDP bytes); a larger delivery is rejected, increments an unsupported-datagram counter, and sends sender TCP ERROR0x85 code10 plus a short diagnostic, at most once per second per sender. Never truncate or assert delivery succeeded. A broadcast can reach new receivers while legacy receivers are rejected.
- Legacy client uplink remains capped1472 for backward compatibility, but that legacy path may require network IP fragmentation above1455. New clients avoid that path above1100 when fragmentation is negotiated; legacy-server fallback is explicitly capped1455.

## Reassembly and abuse bounds

Authenticate token/publicIP/active session and consume wire byte/packet budget before allocating. Per member<=2 incomplete messages; global allocated incomplete payload<=8MiB; timeout2s from first fragment (not renewed). Repeated identical fragment is ignored; conflicting duplicate/partial overlap, changed total/ports/destination, out-of-bounds or invalid lengths invalidate the assembly. Completion requires exact disjoint coverage of every byte (not just summed lengths). Track recently completed IDs for2s (bounded per-member2048 IDs, global65536 IDs) to prevent duplicate replay. Disconnect, leave, new UDP registration and resumed TCP session clear assembly/replay state; never mix across member objects, rooms or sessions. Client similarly bounds2 incomplete messages and aggregate buffered/queued bytes, without a65507*128 static array.

No retransmission protocol is promised: loss of a fragment loses that original UDP datagram, as with normal UDP; never deliver partial/zero-filled data. Heartbeat recovery restores transport readiness, not already-lost game packets.

## Full server-side discovery (approved)

TCP capability bit16. FIND_FILTER request0x0d has exactly101 bytes: existing96-byte ScanFilter (same encoding as RESERVE bytes16..111), features byte at96 (onlyNET13 bit1), u32 offset at97. Requires known flags and nonzero LCID/local-communication-ID flag; older/unsupported filters use legacy discovery. Reply is existingPAGE0x8a (u32nextOffset,u8count,up to6 records of code6+NetworkInfo0x480), after applying complete game/scene/session/type/SSID criteria. End sentinel0xffffffff. Existing per-IP find limits apply; filtering happens before truncation.
